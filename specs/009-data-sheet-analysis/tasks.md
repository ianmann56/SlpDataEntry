# Tasks: Data Sheet Analysis

**Input**: Design documents from `/specs/009-data-sheet-analysis/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md),
[data-model.md](data-model.md),
[contracts/analysis-model-and-formulas.md](contracts/analysis-model-and-formulas.md),
[contracts/analysis-ui.md](contracts/analysis-ui.md), [quickstart.md](quickstart.md)

**Tests**: No automated tests. The spec doesn't ask for them, and research R11 makes
verification:

- offline scratch-script checks of the pure `interpretation/analysis/` modules
  (quickstart V1–V5)
- manual window checks (quickstart V6–V10) in a scratch Workspace

Scratch scripts are not committed.

**Organization**: Tasks are grouped by user story, with the P1 stories first, in spec
order.

- **US1 (P1)**: menu Row Aggregates on a table, the Analysis section, view mode,
  full-screen windows, and renames of sections, columns, fields, and options.
- **US2 (P1)**: layers in full: Arithmetic calculations, lower-layer results, the
  dependency guard, reordering, deleting layers, and calculation renames.
- **US4 (P1)**: existing templates keep loading and saving unchanged.
- **US3 (P2)**: Formula calculations, live checking, the Formula Legend, and formula
  renames.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies on incomplete tasks)
- **[Story]**: US1–US4 from spec.md

## Path Conventions

- **Paths.** All code is under `therepy_sessions/`. Modules import each other by
  package path from that directory (e.g. `from interpretation.analysis.model import Calculation`).
- **Types.** Every public function, method, property, attribute, and `__init__` added
  or changed is fully annotated, per
  [type-declarations.md](../../docs/conventions/architecture/type-declarations.md).
  Records are frozen `@dataclass`es or `NamedTuple`s. Mutable attributes are created in
  `__init__`, never at class level (interpreters rule 3).
- **Purity.** `interpretation/analysis/` imports no Tkinter, does no I/O, and never
  imports `interpreter_types/`, `template_manager/`, or `storage/`. It may import
  `interpretation.value_types` and `interpretation.templates.student_data_sheet_interpreter`
  (for the base class type only).
- **Import order inside `analysis/`.** `parts.py` imports only `value_types`.
  `formula.py` imports nothing from `analysis/`. `model.py` imports `formula.py`.
  `scope.py`, `rules.py`, `renames.py`, and `serialization.py` import `model.py` and
  `formula.py`. Nothing imports `rules.py` except `template_rules.py` and the widgets.
- **Rules out of widgets.** Every choice list comes from `analysis_scope`, and every
  message from `rules.py` (layers rule 5). Widgets only show them.
- **Names.** Template parts are matched ignoring letter case and surrounding spaces
  (`str.strip().casefold()`), everywhere.
- **Privacy.** Use only synthetic template names, such as "Trials" and "Session Info".
  Never use a real student's name.
